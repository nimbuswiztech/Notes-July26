Demonstrating Amazon ECS with AWS Fargate

A definitive, step-by-step console demonstration guide for instructors. Teach your students how to run microservices on AWS serverless compute with zero virtual machines to manage, automatic network isolation, and built-in self-healing.

Target Audience DevOps & Cloud Students
Demo Duration 40 – 50 Minutes
Total Cost < $0.02 (Billed per second)
Compute Engine AWS Fargate (MicroVMs)
01

The Mental Model: What is AWS Fargate?

Lecture: 8 mins
🎙️ Instructor Talk Track (What to say to your students)

"Students, when we ran Docker on our laptops or on a standard EC2 instance, we had to worry about the underlying operating system, kernel patching, disk space, and Docker daemon crashes. AWS Fargate turns compute into a serverless utility. You don't think in terms of servers anymore. You simply tell AWS: 'Here is my container image, give me 0.5 vCPU and 1 GB of RAM', and AWS spins up a dedicated, isolated micro-virtual machine (Firecracker) just for your task within seconds."

Key Takeaway for Students With Fargate, your fundamental unit of compute is the Task, not the EC2 instance!

AWS Fargate Architecture Diagram (Under the Hood)

🛡️ Dedicated MicroVM Isolation

Every Fargate task runs inside its own dedicated kernel microVM (powered by AWS Firecracker). Two tasks never share a kernel, guaranteeing defense-in-depth security.

🌐 Native AWS VPC Networking

Every Fargate task gets its own Elastic Network Interface (ENI) with its own private and public IP address (using the awsvpc network mode).

📈 True Zero-Maintenance Scaling

Scale from 1 to 500 tasks without worrying whether your cluster has enough EC2 worker nodes. AWS provisions capacity on-demand behind the scenes.

Prerequisites & Security Setup

Prep: 5 mins

Before clicking into the ECS Console, ensure the networking and IAM foundation is ready in your AWS Account.

PRE-REQ 1

Create a Web Security Group (ecs-fargate-sg)

AWS Management Console ➔ EC2 ➔ Network & Security ➔ Security Groups ➔ Create security group
Field Name Console Input Value Why This Matters
Security group name ecs-fargate-sg Distinct identifier for the Fargate demo.
Description Allow HTTP inbound traffic for ECS Fargate Clear documentation for students.
VPC Default VPC Ensures public subnets with Internet Gateway route.
Inbound Rule: Type HTTP Port 80 for web server demonstration.
Inbound Rule: Source Anywhere-IPv4 (0.0.0.0/0) Allows students to access the website from their browsers.
💡 Why No SSH (Port 22)?

Fargate has no operating system shell or SSH daemon! If you need to inspect running containers, AWS provides ECS Exec via AWS Systems Manager Session Manager, completely eliminating the need for open SSH ports.

PRE-REQ 2

Verify the Task Execution Role (ecsTaskExecutionRole)

When you create your first task in the modern ECS console, AWS will automatically offer to create this role if it does not already exist. It attaches the managed policy AmazonECSTaskExecutionRolePolicy.

🎙️ Teaching Distinction: Task Execution Role vs. Task Role
  • Task Execution Role: Used by the ECS Agent / Fargate Infrastructure before your container starts (to download your container image from ECR/DockerHub and send logs to CloudWatch).
  • Task Role (Optional): Used by the Application code inside your container (e.g., if your Python or Node.js code needs to read from an S3 bucket or DynamoDB table).

2. Create Public ECR Repository in AWS Console

AWS Console ➔ Amazon Elastic Container Registry (ECR) ➔ Repositories ➔ Select "Public" tab ➔ Create repository
Configuration Field Console Setting Value Explanation
Visibility settings Public Creates repository in the Amazon ECR Public Gallery (accessible globally).
Repository name devops-fargate-app Name of your container image repository.

Click Create repository. Copy your generated Public repository URI (e.g. public.ecr.aws/<your-alias>/devops-fargate-app).

3. Authenticate, Build, Tag & Push (Terminal)

💡 Important ECR Public Authentication Nuance

Amazon ECR Public authentication endpoint is always hosted in region us-east-1! Even if your ECS cluster is in eu-west-1 or ap-south-1, the authentication command must specify --region us-east-1.

Terminal Command: Step 1 - Authenticate Docker to Public ECR 
$ aws ecr-public get-login-password --region us-east-1 | docker login --username AWS --password-stdin public.ecr.aws
Login Succeeded
Terminal Command: Step 2 - Build Local Image 
$ docker build -t devops-fargate-app:v1 .
Terminal Command: Step 3 - Tag Image with Public ECR URI 
# Replace  with your actual alias from ECR console (e.g. k5n8z2d1)
$ docker tag devops-fargate-app:v1 public.ecr.aws/<YOUR-PUBLIC-ALIAS>/devops-fargate-app:v1
Terminal Command: Step 4 - Push to Public ECR 
$ docker push public.ecr.aws/<YOUR-PUBLIC-ALIAS>/devops-fargate-app:v1
The push refers to repository [public.ecr.aws/k5n8z2d1/devops-fargate-app]
v1: digest: sha256:4b910... size: 1362
🔒 Prefer a Private ECR Repository instead? (Click to view commands) ▼
If your organization uses Private ECR repositories, use these regional commands: 
# Authenticate to private ECR
aws ecr get-login-password --region <YOUR-REGION> | docker login --username AWS --password-stdin <ACCOUNT-ID>.dkr.ecr.<YOUR-REGION>.amazonaws.com

# Tag and push
docker tag devops-fargate-app:v1 <ACCOUNT-ID>.dkr.ecr.<YOUR-REGION>.amazonaws.com/devops-fargate-app:v1
docker push <ACCOUNT-ID>.dkr.ecr.<YOUR-REGION>.amazonaws.com/devops-fargate-app:v1

Step 3: Deploy as an ECS Service

Hands-on: 10 mins
STEP 3

Deploy 2 Tasks Behind an ECS Service

ECS Console ➔ Clusters ➔ fargate-demo-cluster ➔ Services tab ➔ Create
🎙️ Teaching Distinction: Standalone Task vs. Service

"Ask your students: 'Why don't we just click Run Task?' A standalone task runs once and dies if it crashes or completes. An ECS Service ensures self-healing and high availability! If we specify Desired Tasks = 2, ECS continuously monitors health. If a container crashes, the Service immediately launches a replacement to maintain exactly 2 tasks running 24/7."

Configuration Section Console Setting Exact Value
Compute options Launch type FARGATE
Deployment configuration Application type Service
Task definition Family / Revision fargate-web-task (revision 1)
Service name Text field fargate-web-service
Desired tasks Number of instances 2
Networking: VPC Dropdown Default VPC
Networking: Subnets Multi-select Select at least 2 Public Subnets
Security group Existing Security Group ecs-fargate-sg (Port 80 open)
Public IP (CRITICAL!) Toggle / Dropdown TURNED ON (Enabled)
Load balancing Optional for basic demo None (or Application Load Balancer)
⚠️ THE #1 CLASSROOM TRAP: Public IP Disabled!

Students frequently leave Public IP turned off or forget to check it. What happens? Because the task is placed in a public subnet without a NAT Gateway, without a Public IP it has no route to the Internet Gateway. The task will get stuck indefinitely in PENDING or fail with:

CannotPullContainerError: inspect image has been retried 1 time(s) ... connection timed out

Emphasize this loudly to your classroom!

Click Create. ECS begins provisioning your serverless service.

Step 5: Classroom Live Demos (Resilience & Scaling)

Demonstration: 6 mins
DEMO A

Simulate a Crash: Test Self-Healing (Desired Count = 2)

Prove to your students that an ECS Service guarantees high availability.

  1. Go to fargate-demo-cluster ➔ Tasks tab.
  2. Select one of the two running tasks by clicking its checkbox.
  3. Click the Stop button at the top right.
  4. Confirm by clicking Stop selected tasks.
🎙️ What to Tell the Class While Waiting 15 Seconds

"Notice the task state becomes STOPPED. Now look at the top bar: the ECS Service deployment controller realizes: 'Hey, my desired count is 2, but I only have 1 task running!' Within seconds, watch a brand-new task appear in state PROVISIONING ➔ PENDING ➔ RUNNING with a new microVM and new IP address. That is production self-healing in action!"

DEMO B

Horizontal Scale-Out: Scale from 2 to 3 Tasks

  1. Inside fargate-demo-cluster, click on the Services tab.
  2. Select fargate-web-service and click Update.
  3. Change Desired tasks from 2 to 3.
  4. Click Update service at the bottom.
  5. Return to the Tasks tab: Observe Task #3 launching instantly!

Step 6: Teardown & Clean-Up (Prevent Billing)

Clean-Up: 3 mins
TEARDOWN

Complete Safe Resource Destruction

💰 Clean-Up Order (Crucial for Students)

Always delete the Service first! If students just stop tasks without deleting the service, the ECS service will endlessly keep launching replacement tasks, consuming resources.

  1. Delete the Service: Go to fargate-demo-cluster ➔ Services tab ➔ select fargate-web-service ➔ click Delete ➔ Check "Force delete service" ➔ Type delete ➔ Confirm.
  2. Delete the Cluster: Click Clusters in the left navigation ➔ select fargate-demo-cluster ➔ click Delete cluster ➔ Type delete fargate-demo-cluster ➔ Confirm.
  3. Deregister Task Definition (Optional): Go to Task definitions ➔ select fargate-web-task ➔ select Revision 1 ➔ Actions ➔ Deregister.
  4. Delete Security Group: EC2 Console ➔ Security Groups ➔ delete ecs-fargate-sg.

Troubleshooting Playbook (Common Student Errors)

Reference
🔴 1. Task is stuck in "PENDING" or fails with "CannotPullContainerError" ▼
Root Cause: The Fargate task cannot connect to the internet to download the image from ECR / Docker Hub.
Fix:
  • Verify that the task was launched in a Public Subnet that has an attached Internet Gateway.
  • Ensure Auto-assign Public IP was set to TURNED ON when creating the service.
  • If using private subnets, ensure a NAT Gateway or AWS VPC Endpoints (for ECR and S3) are configured.
🔴 2. Task status is "STOPPED" with "Essential container in task exited" ▼
Root Cause: The container booted up, but the main application process failed or exited with code 1 or 137.
Fix:
  • Click on the stopped task ➔ open the Containers row.
  • Look at the Exit code and Stopped reason.
  • Click on the Logs tab to see the stack trace printed by the application right before crashing.
🔴 3. Browser hangs or times out when connecting to Public IP:80 ▼
Root Cause: Security Group inbound rule is blocking port 80.
Fix: Go to EC2 Console ➔ Security Groups ➔ ecs-fargate-sg ➔ Inbound Rules. Ensure there is a rule for Type: HTTP, Port: 80, Source: 0.0.0.0/0.
🔴 4. "ResourceInitializationError: unable to pull secrets or registry auth" ▼
Root Cause: The Task Execution Role (ecsTaskExecutionRole) is missing or doesn't have the AmazonECSTaskExecutionRolePolicy attached, preventing the ECS agent from getting ECR auth tokens.
