Demonstrating Amazon ECS with EC2 Launch Type

A definitive, step-by-step console demonstration guide for instructors. Teach your students how ECS manages Docker containers deployed on actual EC2 virtual machines, utilizing Auto Scaling Groups and Dynamic Port Mapping behind an Application Load Balancer.

Target Audience Advanced DevOps Students
Demo Duration 55 – 65 Minutes
Architecture Container Instances + ASG
Networking Bridge Mode & Dynamic Ports
01

The Mental Model: ECS EC2 Launch Type

Lecture: 8 mins
🎙️ Instructor Talk Track (Fargate vs EC2)

"Students, earlier we saw Fargate, where AWS managed the virtual machines for us. But what if we want control over the VMs? What if we have pre-purchased Reserved Instances, or want to use cheaper EC2 Spot Instances, or need direct access to the host OS for security agents?"

"With the EC2 Launch Type, we provide the EC2 instances (workers), and we install the ecs-agent on them. ECS acts as the 'brain' (Control Plane) telling our EC2 instances which Docker containers to run!"

ECS EC2 Architecture & Dynamic Port Mapping

🤯 The "Dynamic Port Mapping" Aha-Moment

This is the most critical concept to teach in this architecture!

"If we deploy a container running Nginx on Port 80 directly to an EC2 instance, it binds to the host's Port 80. What happens if we want to run a SECOND Nginx container on the same EC2 instance? Port conflict! It crashes."

"ECS solves this with Dynamic Port Mapping. The container still thinks it is listening on Port 80, but ECS asks Docker to map it to a random high-numbered port on the EC2 host (e.g., 32768, 32769). ECS then automatically registers these random ports with the Application Load Balancer Target Group. The ALB handles routing port 80 traffic to the random ports seamlessly!"

Step 1: Create ECS Cluster with Auto Scaling Group

Hands-on: 12 mins
STEP 1

Configure the Cluster & Infrastructure

ECS Console ➔ Clusters ➔ Create cluster

Unlike Fargate, creating an EC2-backed cluster means we must tell ECS how to provision the EC2 instances. ECS will automatically create an Auto Scaling Group (ASG) for us!

Configuration Field Console Input Value Why This Matters
Cluster name ec2-demo-cluster Namespace for our EC2 architecture.
Infrastructure Amazon EC2 instances (Check box) CRITICAL: Uncheck AWS Fargate!
Auto Scaling group (ASG) Create new ASG Let ECS build the underlying EC2 pool for us.
Operating system Amazon Linux 2023 Comes pre-installed with Docker & ecs-agent.
EC2 instance type t3.micro (or t2.micro) Free-tier eligible, enough to run a few small containers.
Desired capacity Minimum: 2, Maximum: 3 Provisions 2 EC2 instances immediately.
Network (VPC/Subnets) Default VPC / Any 2 Public Subnets Where the EC2 instances will live.
⚠️ Watch out for EC2 Provisioning Time

When you click Create, it will take 2 to 4 minutes. ECS is launching a CloudFormation stack behind the scenes to create the ASG and boot up the EC2 instances. Wait until the cluster shows 2/2 Container instances registered before proceeding.

Step 2: Create the Application Load Balancer

Hands-on: 10 mins
STEP 2

Pre-provision the ALB & Target Group

Because of Dynamic Port Mapping, we cannot just browse to the EC2 instance's IP address. We MUST use an ALB to handle the traffic routing! We must create the ALB before creating the ECS service.

EC2 Console ➔ Target Groups ➔ Create target group
Target Group Configuration Value
Target type Instances (Because ECS will register the EC2 hosts)
Target group name ecs-ec2-tg
Protocol / Port HTTP / Port 80 (ECS will override this port dynamically later!)

Note: Click Next, DO NOT register any targets manually. Let ECS do that automatically! Click Create target group.

EC2 Console ➔ Load Balancers ➔ Create Load Balancer ➔ ALB
ALB Configuration Value
Load balancer name ecs-ec2-alb
Scheme Internet-facing
Network mapping Default VPC, Select at least 2 public subnets
Security groups Select a SG that allows HTTP Port 80 from 0.0.0.0/0
Listener / Routing Forward to: ecs-ec2-tg
04

Step 3: Create Task Definition (Bridge Mode)

Hands-on: 8 mins
STEP 3

Configure the Task with Dynamic Port Mapping

ECS Console ➔ Task definitions ➔ Create new task definition
Configuration Field Console Input Value Why This Matters
Task definition family ec2-web-task Name of the blueprint.
Launch type Amazon EC2 instances Required to deploy to our EC2 instances!
Network mode Bridge CRITICAL: Uses the EC2 host's Docker daemon bridge network (docker0).
Task CPU / Memory Leave Blank! Optional for EC2 launch type! We will define limits at the container level.

Container Configuration

Field Name Console Input Value Notes
Name web-app Container identifier.
Image URI public.ecr.aws/ecs-sample-image/amazon-ecs-sample:latest The AWS sample web application.
Port Mappings Container Port: 80 | Host Port: 0 (Zero) THE MAGIC! Setting Host Port to 0 enables Dynamic Port Mapping!
Memory Limit (Hard limit) 256 MB Prevents one container from eating all EC2 RAM.
💡 Why Host Port = 0?

By explicitly setting the Host Port to 0, you are instructing Docker and ECS to grab an available ephemeral port (between 32768 - 65535) on the EC2 instance and bind it to the container's port 80. This allows multiple containers to run on the exact same EC2 instance without port conflicts.

Step 4: Deploy the ECS Service

Hands-on: 10 mins
STEP 4

Deploy 4 Tasks and Attach the ALB

ECS Console ➔ Clusters ➔ ec2-demo-cluster ➔ Services ➔ Create
Configuration Section Console Setting Exact Value
Compute options Launch type EC2 (Ensure Fargate is NOT selected)
Task definition Family / Revision ec2-web-task
Service name Text field ec2-web-service
Desired tasks Number of instances 4 (We only have 2 EC2s. Proves dynamic ports work!)

Load Balancing Configuration

Expand the Load Balancing section to connect ECS to the ALB we created in Step 2.

ALB Configuration Field Value
Load balancer type Application Load Balancer
Container to load balance web-app:80:0 (Select from dropdown)
Use an existing load balancer ecs-ec2-alb
Listener Use an existing listener (80:HTTP)
Target group Use an existing target group (ecs-ec2-tg)

Click Create.

Step 5: Verify ALB & Dynamic Ports

Demonstration: 7 mins
DEMO

Show the Class How ECS Updated the Target Group

This is the climax of the demonstration. We want to prove to students that ECS took the 4 tasks and automatically registered their random ports with the Load Balancer!

  1. Go to EC2 Console ➔ Target Groups.
  2. Select ecs-ec2-tg and open the Targets tab.
  3. Show the students: You will see 4 targets registered. Notice the Port column! It won't be 80. It will be random high ports like 32768, 41056, etc.
  4. Notice the Instance ID column: Two tasks will share Instance A, and two tasks will share Instance B.

The Final Test

  1. Go to Load Balancers in the EC2 Console.
  2. Select ecs-ec2-alb and copy the DNS Name (e.g., ecs-ec2-alb-12345.us-east-1.elb.amazonaws.com).
  3. Paste it into your browser.
  4. You will see the Amazon ECS Sample App. Refresh the page rapidly—you will see the underlying container ID change as the ALB round-robins traffic across all 4 dynamically-mapped tasks!

Step 6: Teardown & Clean-Up

Clean-Up: 5 mins
TEARDOWN

Destroy Infrastructure (Prevent Billing!)

Because we are using actual EC2 instances and Load Balancers, failing to clean up this lab will result in hourly charges!

  1. Delete the ECS Service: ECS Console ➔ Clusters ➔ ec2-demo-cluster ➔ Services tab ➔ Delete ec2-web-service (Force delete).
  2. Delete the ECS Cluster: In the cluster view, click Delete Cluster.
    Note: Because ECS created the Auto Scaling Group for you, deleting the cluster will automatically trigger CloudFormation to terminate the EC2 instances!
  3. Delete the ALB: EC2 Console ➔ Load Balancers ➔ Delete ecs-ec2-alb.
  4. Delete the Target Group: EC2 Console ➔ Target Groups ➔ Delete ecs-ec2-tg.
