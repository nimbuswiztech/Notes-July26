01

Git Fundamentals & Git vs GitHub

Git is the version-control tool used to track changes, create versions, branch, merge and collaborate. GitHub is a hosting/collaboration platform that can store Git repositories and provide pull requests, reviews and issues.

Quick check
git --version
git status
git log
02

Installation & Configuration

The classroom notes demonstrate installing Git on an EC2/Linux machine and configuring the user name and email before committing. Identity configuration is separate from remote authentication.

Linux install
sudo yum install git
# Debian/Ubuntu:
sudo apt-get install git
Identity
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Verify
git --version
which git
03

Repository & .git Directory

A directory becomes a Git repository after git init. The hidden .git directory contains the metadata needed by Git.

Create
mkdir git
cd git
git init
ls -a
Check
ls -a
# .git should be present
04

Git Architecture — Workspace to Remote

The supplied notes describe four stages: Workspace → Staging Area → Local Repository → Central Repository. Files are edited in the workspace, selected with git add, committed locally, and pushed to the central repository.

Flow
vi file1
git status
git add file1
git commit -m "add file1"
git push
05

Basic Workflow — Status, Add & Commit

git status shows whether files have changes in the working tree or staging area. git add moves selected changes into the staging area. git commit creates a version in the local repository.

Demo
vi file1
git status
git add file1
git status
git commit -m "add file1"
git status
06

Clone a Repository

git clone brings an existing remote repository to the local machine, including its working files and history.

HTTPS
git clone https://github.com/username/projectname.git
SSH
git clone git@github.com:username/projectname.git
Custom directory
git clone https://github.com/username/projectname.git MyFolder
07

Remote Repositories

Remotes give names to shared repositories. origin is commonly used for the main remote; upstream is often used for the original repository when working from a fork.

Manage remotes
git remote -v
git remote add origin <remote-url>
git remote show origin
git remote get-url origin
git remote set-url origin <new-url>
git remote rename origin upstream
git remote remove upstream
08

SSH Setup for Git

The supplied reference covers checking ~/.ssh, generating a key, adding it to ssh-agent and changing an existing remote to SSH.

SSH key
ls -al ~/.ssh
ssh-keygen
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
Remote
git remote set-url origin git@github.com:username/repository.git
09

Git History & Log

git log displays repository history. The reference also covers compact, graph, filtered and searchable log formats.

Common
git log
git log -n
git log --oneline
git log --decorate --oneline --graph
git show <commit-id>
Search
git log --grep "search_string"
git log -S"text"
git log -G"pattern"
git shortlog -s -n
10

Staging & Diff

The reference includes staging all changes, staging a single file, staging by hunk, viewing staged changes, and comparing commits or branches.

Stage
git add .
git add <file>
git add -p
Diff
git diff
git diff --staged
git diff <commit1> <commit2>
git diff <branch1>..<branch2>
11

.gitignore

A .gitignore file tells Git which files or directories should be ignored. Typical examples include logs, local environment files and build output. If a file is already tracked, adding it to .gitignore does not by itself remove it from tracking.

Example
.gitignore
*.log
.env
target/
node_modules/
.idea/
Check ignored files
git check-ignore -v <file>
git status --ignored
12

Branching

Branching supports parallel development. Developers can create feature or fix branches, work independently and later integrate them.

Commands
git branch
git branch feature/login
git checkout feature/login
git checkout -b feature/payment
git branch -d feature/login
git branch -m oldname newname
13

Merging & Merge Conflicts

git merge integrates a source branch into the currently checked-out branch. Conflicts can occur when Git cannot automatically reconcile changes, such as competing edits to the same part of a file.

Merge
git checkout main
git merge feature/login
Conflict workflow
git status
# edit conflicted files
git add <resolved-file>
git commit
Abort
git merge --abort
14

Revert vs Reset

The supplied notes distinguish git revert and git reset. Revert reverses an existing change by creating a new commit, while reset moves the branch reference and can remove commits from the current branch history.

Revert
git revert <commit-id>
Reset
git reset --soft <commit-id>
git reset --mixed <commit-id>
git reset --hard <commit-id>
15

Rebase

Rebase integrates work by replaying commits on a new base and rewrites commit history. The source explicitly contrasts this with merge, which creates a merge commit when appropriate.

Basic
git checkout feature
git rebase main
Interactive
git rebase -i HEAD~n
Conflict recovery
git add <resolved-file>
git rebase --continue
# or
git rebase --abort
16

Squashing Commits

Squashing condenses multiple commits into fewer meaningful commits so the project history is clearer. The supplied notes use interactive rebase for this.

Command
git rebase -i HEAD~n
17

Stash — Save Work in Progress

The classroom scenario is: work is in progress on one branch, an urgent fix is required elsewhere, and you do not want to create a normal commit. Stash the work, switch branches, fix the issue, then restore the work.

Commands
git stash
git stash list
git stash pop
git stash apply
git stash drop
18

Cherry-Pick

Cherry-pick applies a specific commit onto the currently checked-out branch. It is useful when you need one particular change without merging an entire branch.

Command
git cherry-pick <commit-id>
19

Tagging

A tag is a name given to a point in repository history and is commonly used for milestones or releases. A branch is intended for an ongoing development line.

Commands
git tag v1.0.0
git tag
git checkout v1.0.0
git tag -d v1.0.0
git push origin v1.0.0
git push origin --tags
20

Fetch, Pull & Push

The supplied notes summarize clone as the first copy from the central repository, pull as bringing changes and integrating them locally, fetch as downloading remote changes for review, and push as moving local changes to the central repository. The notes summarize pull as fetch + merge.

Commands
git fetch origin
git pull origin main
git push origin main
21

Upstream & Fork Workflow

When working from a fork, origin can point to your copy while upstream points to the original project. This allows changes to be fetched from the original repository while development is pushed to your fork.

Example
git remote -v
git remote add upstream https://github.com/projectusername/repo.git
git fetch upstream
git checkout main
git merge upstream/main
22

Git Workflows

The supplied Git reference covers Centralized Workflow, Gitflow Workflow, Feature Branch Workflow, GitHub Flow and Forking Workflow.

Feature flow
git checkout -b feature/login
git add .
git commit -m "Add login"
git push -u origin feature/login
23

Commit Messages & Amend

The reference includes good commit messages and amending a commit. Amend is commonly used when the latest commit needs its message or staged content corrected.

Amend
git commit --amend -m "New commit message."
24

Reflog & Recovery

Reflog records local reference movements and is useful when recovering from reset, rebase, deleted branches or other situations where a commit is no longer visible in normal git log output.

Recovery checks
git reflog
git log --oneline --decorate --graph --all
git branch -a
git status
25

Git Clean

git clean removes untracked files and directories. The reference covers previewing, interactive cleanup, forceful cleanup and ignored-file cleanup.

Commands
git clean -n
git clean -i
git clean -f
git clean -fd
git clean -fdX
26

Git Hooks

Hooks are scripts associated with Git lifecycle events. The reference covers pre-commit, commit-msg, pre-push, post-commit, pre-rebase, pre-receive and post-receive among others.

Location
.git/hooks/
Examples
pre-commit
commit-msg
pre-push
post-commit
pre-rebase
pre-receive
post-receive
27

Submodules

A submodule allows one Git repository to include another repository at a selected revision. The reference covers cloning with submodules, adding, updating, following branches, moving and removing them.

Commands
git submodule add <repo-url> path/to/module
git clone --recurse-submodules <repo-url>
git submodule update --init --recursive
git submodule update --remote
28

Worktrees

Git worktrees provide multiple working directories associated with one repository, useful when you need to work on another branch without changing the current working directory.

Commands
git worktree add ../hotfix hotfix
git worktree list
git worktree remove ../hotfix
29

Bisect & Blame

git bisect performs a binary search through commit history to identify a faulty commit. git blame identifies the commit/author associated with lines in a file.

Bisect
git bisect start
git bisect bad
git bisect good <known-good-commit>
# test each checkout
git bisect good
git bisect bad
git bisect reset
Blame
git blame <file>
git blame -L <start>,<end> <file>
30

Git LFS, Patch & Archive

The supplied reference covers Git Large File Storage, creating/applying patches and creating repository archives.

LFS
git lfs install
git lfs track "*.zip"
git add .gitattributes
git add <large-file>
git commit -m "Track large files with LFS"
Patch
git diff > change.patch
git apply change.patch
Archive
git archive --format=zip --output=project.zip HEAD
31

Bare vs Non-Bare Repository

A bare repository contains Git data without a working tree and is commonly used as a remote repository. A non-bare repository has a working tree where files can be edited.

Commands
git init --bare /path/to/repo.git
git init
32

Git Fork

Forking creates a copy of a repository under another account. It is commonly used when a developer does not have direct push access to the original project and needs to propose changes back to it.

Model
Original repository
   ↓ fork
Personal repository
   ↓ clone
Local repository
   ↓ push
Personal repository
   ↓ pull request
Original repository
