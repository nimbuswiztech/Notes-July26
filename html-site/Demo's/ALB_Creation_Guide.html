AWS ALB with Path-Based Routing Guide

This guide demonstrates how to set up an Application Load Balancer (ALB) to route traffic to different target groups based on the requested URL path (e.g., /billing.html vs /payment.html). We will deploy 5 EC2 instances in total: 2 for billing, 2 for payment, and 1 as a default target.

Phase 1: Launching EC2 Web Servers

Step 1: Launch 5 EC2 Instances

Launch 5 identical Amazon Linux instances (e.g., t2.micro) to serve as our web servers. Use an existing key pair and a security group that allows HTTP (Port 80) and SSH (Port 22) traffic from anywhere.

  • Name them clearly: ALB-Server-Default, ALB-Server-Billing1, ALB-Server-Billing2, ALB-Server-Payment1, ALB-Server-Payment2.
  • User Data: Use the following bash script for all instances to install and start Apache automatically on boot.
#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>Default Homepage</h1>" > /var/www/html/index.html

Step 2: Configure Custom Pages via SSH

We need to create specific HTML files so our load balancer health checks can pass and we can verify routing.

  1. Default Server: Leave it as is. It already has index.html.
  2. Billing Servers (x2): SSH into both billing servers and rename the index file to billing.html. Add billing-specific text. 
    sudo su
cd /var/www/html
mv index.html billing.html
echo "<h1>Welcome to the Billing Page!</h1>" > billing.html
  3. Payment Servers (x2): SSH into both payment servers and rename the index file to payment.html. Add payment-specific text. 
    sudo su
cd /var/www/html
mv index.html payment.html
echo "<h1>Welcome to the Payment Page!</h1>" > payment.html

Phase 2: Creating Target Groups

Step 3: Create Three Target Groups

Navigate to EC2 Dashboard > Target Groups and create the following three Target Groups (Type: Instances, Protocol: HTTP, Port 80):

  1. Default Target Group:
    • Name: Default-TG
    • Health Check Path: /index.html (or just /)
    • Register target: Select the 1 Default server.
  2. Billing Target Group:
    • Name: Billing-TG
    • Health Check Path: /billing.html
    • Register targets: Select the 2 Billing servers.
  3. Payment Target Group:
    • Name: Payment-TG
    • Health Check Path: /payment.html
    • Register targets: Select the 2 Payment servers.
Note: Under Advanced Health Check settings, you can adjust the interval to 10 seconds to speed up the health check process. Wait until targets show as Healthy before proceeding.

Phase 3: Creating the Application Load Balancer

Step 4: Configure the ALB

  1. Navigate to EC2 Dashboard > Load Balancers and click Create load balancer. Select Application Load Balancer.
  2. Name: e.g., Nimbus-ALB
  3. Scheme: Internet-facing
  4. Network mapping: Select at least two Availability Zones where your instances are deployed (e.g., us-east-1a and us-east-1b).
  5. Security groups: Select your web security group allowing Port 80.
  6. Listeners and routing:
    • Protocol: HTTP, Port: 80
    • Default action: Forward to Default-TG
  7. Click Create load balancer and wait for the state to become Active.

Step 5: Configure Path-Based Routing Rules

Now we will tell the ALB how to route traffic based on the URL path.

  1. Select your ALB and go to the Listeners and rules tab.
  2. Click on the HTTP:80 listener to view its rules.
  3. Click Manage rules (or Add rule).
  4. Add Rule 1 (Billing):
    • Condition: Path is /billing.html
    • Action: Forward to Billing-TG (Weight: 100%)
    • Priority: 1
  5. Add Rule 2 (Payment):
    • Condition: Path is /payment.html
    • Action: Forward to Payment-TG (Weight: 100%)
    • Priority: 2

Phase 4: Testing the Setup

Step 6: Verify Traffic Distribution

  1. Copy the DNS name of your Application Load Balancer.
  2. Test Default: Paste the DNS name in your browser. It should hit the Default target and show "Default Homepage".
  3. Test Billing: Append /billing.html to the DNS name (e.g., nimbus-alb-123.us-east-1.elb.amazonaws.com/billing.html). You should see the Billing Page. Refresh multiple times to verify traffic balances between your two billing instances.
  4. Test Payment: Append /payment.html to the DNS name. You should see the Payment Page. Refresh to see load balancing across the two payment instances.
