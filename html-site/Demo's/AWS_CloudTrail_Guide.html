📘 AWS Teaching Guide – Day Session

AWS CloudTrail

Complete audit logging and governance for every API call in your AWS account. Who did what, when, and from where.

🕐 45–60 Minutes 🎯 Intermediate 🔍 Audit & Compliance 🔗 Integrates with CloudWatch, S3, SNS
🔍

What is AWS CloudTrail?

🏛️ Real-World Analogy — CCTV for Your AWS Account

Imagine your AWS account is a secure office building. Every door has a badge reader — every time someone enters a room (makes an API call), it logs: who entered, which room, what time, and from which entry point. CloudTrail is that badge reader system — recording every single AWS action.

Core Definition

AWS CloudTrail is a service that records all API calls made in your AWS account — through the Console, CLI, SDK, or other AWS services. Every action creates an event stored as a JSON log file.


📋

What it records

Every API call: who called, which service, what action, what resource, when, from which IP/region.

📦

Where logs go

Delivered as compressed JSON files to an S3 bucket. Optionally streamed to CloudWatch Logs.

🌍

Scope

Can be per-region or multi-region (Organisation trail covers all accounts in an AWS Org).

Key Terminology

TermDefinitionExample
TrailConfiguration that captures events and delivers them to S3"MyCompanyAuditTrail"
EventA single API call record (JSON object)ec2:RunInstances by user@company.com
Management EventsControl-plane operations (create, delete, modify resources)CreateBucket, StopInstances
Data EventsData-plane operations within a resourceS3:GetObject, Lambda:Invoke
Insights EventsAI-detected unusual API activity patternsSpike in TerminateInstances calls
Event HistoryFree 90-day rolling history — no trail neededView in Console → CloudTrail → Event History
⚙️

How CloudTrail Works — Architecture

End-to-End Flow

User / Service makes API Call
→
AWS API Endpoint receives call
→
CloudTrail intercepts & records event
→
JSON log → S3 Bucket
→
Optional: CloudWatch Logs / SNS Alert
AWS Account ├── IAM User "alice" runs: aws s3 mb s3://my-new-bucket (CLI) │ └── CloudTrail captures event: { "eventVersion": "1.08", "userIdentity": { "type": "IAMUser", "userName": "alice", "arn": "arn:aws:iam::123456789012:user/alice" }, "eventTime": "2024-09-02T09:15:32Z", "eventSource": "s3.amazonaws.com", "eventName": "CreateBucket", "sourceIPAddress": "203.0.113.45", "requestParameters": { "bucketName": "my-new-bucket" }, "responseElements": { "location": "/my-new-bucket" }, "awsRegion": "ap-south-1" } │ ├── Delivered to → s3://my-audit-trail-bucket/AWSLogs/123456789012/CloudTrail/ap-south-1/2024/09/02/ └── Streamed to → CloudWatch Log Group: /aws/cloudtrail/audit

Event Categories — Teach with Examples

Management Events (Default ON — Free)

  • ✅ ec2:RunInstances — Launch an EC2 instance
  • ✅ ec2:TerminateInstances — Terminate EC2
  • ✅ s3:CreateBucket — Create S3 bucket
  • ✅ iam:CreateUser — New IAM user
  • ✅ iam:AttachRolePolicy — Attach policy to role
  • ✅ rds:CreateDBInstance — Create RDS
  • ✅ cloudformation:CreateStack — Deploy stack

Data Events (Optional — Charged per 100K events)

  • 📂 s3:GetObject — Download a file from S3
  • 📂 s3:PutObject — Upload a file to S3
  • 📂 s3:DeleteObject — Delete a file from S3
  • λ lambda:InvokeFunction — Lambda execution
  • 🗄️ dynamodb:PutItem — Write to DynamoDB
⚠️
Cost Alert: Enable Data Events only on specific critical buckets/functions — not account-wide — to avoid large bills.
🛠️

Hands-On: Creating a Trail (Step-by-Step)

Lab 1: Create Your First Multi-Region Trail

ℹ️
Goal: Create a trail that logs all management events across all regions and delivers them to an S3 bucket. This is the standard production setup.
1
Open CloudTrail Console Go to AWS Console → Services → CloudTrail. Click "Create trail".
2
Configure Trail Name & Scope
  • Trail name: my-company-audit-trail
  • ✅ Enable for all regions — Check "Apply trail to all regions" → catches events even if someone switches to us-west-2
  • ✅ Enable for all accounts in organization — If using AWS Org (optional)
3
Configure S3 Bucket for Log Storage
  • Select "Create a new S3 bucket"
  • Bucket name: my-cloudtrail-logs-2024 (must be globally unique)
  • ✅ Enable SSE-S3 encryption (or SSE-KMS for compliance)
  • ✅ Enable Log file validation — generates SHA-256 digest to detect tampering
✅
CloudTrail automatically attaches a bucket policy to the S3 bucket allowing CloudTrail to write to it. You don't need to configure this manually.
4
Configure CloudWatch Logs (Optional but Recommended)
  • ✅ Enable "CloudWatch Logs" toggle
  • Log group name: /aws/cloudtrail/audit
  • Create new IAM role (CloudTrail will create it automatically)
  • This allows real-time alerting via CloudWatch Alarms + SNS
5
Choose Events to Log
  • ✅ Management Events → Read + Write (default)
  • ⬜ Data Events → Leave unchecked (enable only if needed for specific S3 buckets)
  • ⬜ Insights Events → Enable if you want anomaly detection (extra charge)
6
Review & Create Review the summary. Click "Create trail". The trail becomes active immediately.
⚠️
CloudTrail delivers log files within ~15 minutes of the API call being made — there is a short delay.
🔬 Lab 2: Verify Trail is Working — Query Event History
After creating the trail, trigger some events and find them in Event History
  1. In the AWS Console, go to CloudTrail → Event History
  2. Filter by Event name: CreateTrail — you should see the trail creation you just did
  3. Click the event → View the full JSON — point out: userName, sourceIPAddress, eventTime, requestParameters
  4. Now do something: Create an S3 bucket from Console → come back to Event History → Filter by CreateBucket — appears within 1-2 minutes
  5. Show students: Event History only goes back 90 days and only shows Management Events
🔬 Lab 3: Look Up Logs in S3
Find the actual CloudTrail log files in S3 and inspect the JSON
  1. Go to S3 → find bucket my-cloudtrail-logs-2024
  2. Navigate to prefix: AWSLogs/<ACCOUNT-ID>/CloudTrail/<REGION>/<YEAR>/<MONTH>/<DAY>/
  3. Download a .json.gz file and inspect it (or use S3 Select to query inline)
  4. Show the structure: each file contains an array of Records[] — each record is one API call
  5. Use AWS CLI to query: aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=CreateBucket

Real-World Use Cases — Teach with Scenarios

Scenario 1: Security Incident — Who Deleted the S3 Bucket?

🚨
Incident: Production S3 bucket "company-prod-data" was deleted at 2 AM. Your team needs to find who did it.
→
Query CloudTrail Event History:
Filter by Event Name: DeleteBucket, Time range: last 24 hours.
The event shows: IAM user "john.doe" deleted the bucket from IP 185.x.x.x at 02:14:32 UTC
💡
Teaching Point: Without CloudTrail, this is impossible to investigate. With CloudTrail, the full audit trail is always available.
aws cloudtrail lookup-events \ --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteBucket \ --start-time 2024-09-01T00:00:00Z \ --end-time 2024-09-02T00:00:00Z \ --query 'Events[*].{User:Username,Time:EventTime,Event:EventName}'

Scenario 2: Compliance Audit — Prove No Unauthorized IAM Changes

Your security team must prove that no new IAM users were created in the past 30 days without approval.

aws cloudtrail lookup-events \ --lookup-attributes AttributeKey=EventName,AttributeValue=CreateUser \ --start-time 2024-08-01T00:00:00Z \ --query 'Events[*].{User:Username,NewUser:CloudTrailEvent}' \ --output table
✅
CloudTrail logs are admissible evidence for SOC 2, PCI-DSS, HIPAA, and ISO 27001 compliance audits because log file validation ensures they haven't been tampered with.

Scenario 3: Real-Time Alert — Root Account Login

You want an immediate email alert whenever the AWS root account logs in (a critical security event).

CloudTrail logs ConsoleLogin by root
→
CloudWatch Logs (stream from trail)
→
CloudWatch Metric Filter
→
CloudWatch Alarm → SNS → Email

CLOUDWATCH METRIC FILTER PATTERN
{$.userIdentity.type = "Root" && $.eventName = "ConsoleLogin"}

Set alarm: if count >= 1 → Send SNS alert to security@company.com immediately.

CloudTrail Insights — Anomaly Detection

What is CloudTrail Insights?

CloudTrail Insights uses machine learning to detect unusual API activity patterns — automatically, without you writing any rules.


Examples of Insights it detects:

  • 🚨 Sudden spike in TerminateInstances calls (crypto-miner cleaning up)
  • 🚨 Unusual volume of CreateAccessKey calls (attacker creating backdoors)
  • 🚨 Spike in DeleteSnapshot calls (ransomware attack)
  • 🚨 Abnormal GetSecretValue call volume (credential harvesting)
💡
How it works: CloudTrail baselines normal API call rates over 7 days. If call volume deviates significantly, it creates an Insights event. Cost: $0.35 per 100K management events analyzed.
🔒

Log File Integrity Validation

Why it matters

An attacker who gains access to your S3 bucket might try to delete or modify CloudTrail logs to cover their tracks. Log file validation detects this tampering.

🔐
How it works: Every hour, CloudTrail creates a digest file containing SHA-256 hashes of all log files delivered in that period. The digest itself is signed with CloudTrail's private key. You can validate that no files have been deleted or modified using:
aws cloudtrail validate-logs \ --trail-arn arn:aws:cloudtrail:ap-south-1:123456789012:trail/my-company-audit-trail \ --start-time 2024-09-01T00:00:00Z

Output: Logs validated. No log files were modified, deleted, or forged.

📚 Session Summary — CloudTrail Key Takeaways

  • CloudTrail records EVERY API call — Console, CLI, SDK, AWS services
  • Event History = free 90-day lookup, no configuration needed
  • Trails = persistent, delivered to S3, can stream to CloudWatch
  • Management Events = who created/deleted/modified resources (free on first trail)
  • Data Events = inside-resource operations (S3 GetObject etc.) — charged
  • Log File Validation = detects if logs are tampered with (SHA-256 digest)
  • CloudTrail Insights = ML-based anomaly detection on API call patterns
  • Key use cases: Security investigation, compliance audits, real-time alerts
  • Always enable a multi-region trail on every AWS account from Day 1
