JFrog Artifactory - Zero to Pro Guide [Part 1]

🕒 Last Updated: 2026-09-22 👨‍💻 Author: Cloud Engineer

JFrog Artifactory - Zero to Pro Guide [ Part 1 ]

Hi Amigos! In this blog, we are going to discuss one of the important DevOps tools called JFrog Artifactory, it is useful for managing binaries and artifacts throughout the software development and delivery process.

It acts as a central hub for storing, managing, securing, and distributing all types of software artifacts, including:

  • Package types : Maven, Gradle, NuGet, npm, Python, RubyGems, Docker, Helm, Conan, Generic, and more
  • File types : JARs, WARs, EARs, ZIPs, RPMs, DEBs, ISOs, DLLs, SOs, APKs, IPAs, and more
  • Container images : Docker, Helm etc

Let’s see Repo types along with the process of creating it

1. Local Repository :

Local repositories are physical, locally managed repositories into which you can deploy artifacts.

These are the actual repos where we going to store our Artifacts. In IT standards, the repos was created based on the Region based Servers.

1

Steps to create it

Login into the Jfrog Server → Go to the Admin Tab → Repositories → Local and Click ‘Create’ → Select Package type ( maven, Generic etc ) → Repo Key ( Name of the Repo ) → Layout → Description

Repo Layout : A repository layout defines the structure of how artifacts are stored within a repository. It determines the hierarchical arrangement of files and folders, enabling tailored organization for different artifact types and access patterns.

Eg : For maven layout ( pom.xml )

xml 
<groupId>com.example</groupId>
<artifactId>my-artifact</artifactId>
<version>1.0.0</version>
<packaging>jar</packaging>

Layout : /com/example/my-artifact/1.0.0/my-artifact-1.0.0.jar

Had a question what if we upload artifact with same version again? You can avoid by using option like below mvn deploy -DuniqueVersion=true ( will create unique path ).

Include / Exclude pattern : Helps to filter files or folders that should be included or excluded within the repository’s scope.

2. Remote Repository :

A remote repository serves as a caching proxy for a repository managed at a remote URL. Artifacts are stored and updated in remote repositories according to various configuration parameters that control the caching and proxying behavior.

You can remove artifacts from a remote repository cache but you cannot actually deploy a new artifact into a remote repository.

Example Scenario :

Let say, you have a local repository on US location. So, when you try to access the repo directly from that Location. There might be latency, network related issue happens.

To avoid these situations, We can create a Remote repo on Indian region and add our Local repo ( which located on Remote loc ). So, the artifacts will be cached on this location.

2

Steps to create it

Login into the Jfrog Server → Go to the Admin Tab → Repositories → Remote and Click ‘Create’ → Select Package type ( maven, Generic etc ) → Repo Key ( Name of the Repo ) → Paste the URL of the source repo or local repo → Then, give the Username and Password and test the connection → choose other options like repo layout, Public desc, etc

Also, you can use the Maven central URL as well if needed.

Now, Go to Advanced Tab → Choose proxy setting if needed → Then, provide Artifacts cleanup Actions accordingly.

3. Virtual Repository :

A virtual repository aggregates several repositories with the same package type under a common URL.

When an artifact is requested from a virtual repository, the order in which repositories are searched or resolved is local repositories first, then remote repository caches, and finally remote repositories themselves.

Within each of these, the order by which repositories are queried is determined by the order in which they are listed in the configuration as described in General Resolution Order below.

So, virtual repo is just a combination of Local and Remote Repo.

3

Steps to create it

Login into the Jfrog Server → Go to the Admin Tab → Repositories → Virtual and Click ‘Create’ → Select Package type ( maven, Generic etc ) → Repo Key ( Name of the Repo ) → Layout → Description

Same process, only thing you have to do is selecting the Repos that you want to replicate under this virtual Repo.

We can upload files directly to virtual Repo, but we must click “Default Deployment Repository” and choose a repo. So, whenever you upload files to virtual. It will go to the repo mentioned here.

4. Federated Repository :

It is a collection of Federated repositories in up to 10 repos at different sites that are automatically configured for full bi-directional replication. Once you have set up the Federation, changes made to artifacts on one site will be automatically synchronized to the other JPDs in the Federation using bi-directional mirroring.

Any of the CRUD actions that you perform are automatically applied to the member Federated repositories. Users can perform actions according to their permission sets. The logic is applied according to the last action performed on the artifact by any of the users in the Federation.

Same Creation Process, just add the repo under Federation tab.
