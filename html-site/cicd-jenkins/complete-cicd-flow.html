Complete CI/CD Flow Implementation

🕒 Last Updated: 2026-09-22 👨‍💻 Author: Cloud Engineer

1. Architecture Diagram

⭐ FEATURED ARCHITECTURAL BLUEPRINT • CI/CD Pipeline Workflow
Complete DevOps CI/CD Pipeline Architecture: Source Code → Build → Code Quality → Artifact Repository → Deployment

2. Jenkinsfile

This is the complete Declarative Pipeline script implementing the architecture above. It handles checking out code, building with Maven, static code analysis via SonarQube, uploading to Artifactory, deploying to Tomcat via SSH, and pushing to Docker Hub.

Jenkinsfile 
pipeline {
    agent any

    environment {
        PATH = "$PATH:/usr/share/maven/bin"

        ARTIFACTORY_URL = 'http://13.218.210.102:8081/artifactory'
        ARTIFACTORY_REPO = 'libs-release-local'

        TOMCAT_HOST = '98.89.2.8'
        TOMCAT_USER = 'ubuntu'
        TOMCAT_WEBAPPS = '/opt/tomcat/webapps'
    }

    stages {
        stage('GetCode') {
            steps {
                git(
                    branch: 'main',
                    changelog: false,
                    poll: false,
                    url: 'https://github.com/nimbuswiztech/Petclinic.git'
                )
            }
        }

        stage('Build') {
            steps {
                sh '''
                    set -e
                    mvn clean package
                    ls -lh target/*.war
                '''
            }
        }
        stage('SonarQube Analysis') {
            steps {
                withSonarQubeEnv('SonarQube-Server') {
                    sh 'mvn org.sonarsource.scanner.maven:sonar-maven-plugin:sonar'
                }
            }
        }
        
        stage('Test Artifactory') {
            steps {
                withCredentials([
                    usernamePassword(
                        credentialsId: 'Jfrog-Server',
                        usernameVariable: 'JFROG_USER',
                        passwordVariable: 'JFROG_PASSWORD'
                    )
                ]) {
                    sh '''
                        set -e
                        echo "Testing Artifactory connection..."
                        curl --fail --silent --show-error \\
                            -u "$JFROG_USER:$JFROG_PASSWORD" \\
                            "$ARTIFACTORY_URL/"
                        echo ""
                        echo "Artifactory connection successful."
                    '''
                }
            }
        }

        stage('Upload to Artifactory') {
            steps {
                withCredentials([
                    usernamePassword(
                        credentialsId: 'Jfrog-Server',
                        usernameVariable: 'JFROG_USER',
                        passwordVariable: 'JFROG_PASSWORD'
                    )
                ]) {
                    sh '''
                        set -e

                        WAR_FILE=$(ls target/*.war | head -n 1)
                        ARTIFACT_URL="$ARTIFACTORY_URL/$ARTIFACTORY_REPO/com/dme/app/my-app/3.0/my-app-3.0.war"

                        echo "Uploading .war to Artifactory..."
                        curl --fail --silent --show-error \\
                            -u "$JFROG_USER:$JFROG_PASSWORD" \\
                            --upload-file "$WAR_FILE" \\
                            "$ARTIFACT_URL"

                        echo ""
                        echo "Artifact uploaded successfully."
                        echo "$ARTIFACT_URL"
                    '''
                }
            }
        }

        stage('Deploy to Tomcat') {
            steps {
                sshPublisher(
                    publishers: [
                        sshPublisherDesc(
                            configName: 'Tomcat-Server',
                            verbose: true,
                            transfers: [
                                sshTransfer(
                                    sourceFiles: 'target/*.war',
                                    removePrefix: 'target',
                                    remoteDirectory: 'webapps'
                                )
                            ]
                        )
                    ]
                )
            }
        }

        stage('Docker Build & Push') {
            steps {
                script {
                    withDockerRegistry(credentialsId: 'dockerhub', toolName: 'docker') {
                        sh 'docker build -t nimbuswiztech/july26:petclinic .'
                        sh 'docker push nimbuswiztech/july26:petclinic'
                    }
                }
            }
        }
    }

    post {
        success {
            echo 'Build → Artifactory → Tomcat deployment completed successfully.'
        }

        failure {
            echo 'Pipeline failed. Check the failed stage above.'
        }
    }
}

3. Required Jenkins Plugins

  • Git Plugin: To pull the source code from GitHub repositories.
  • Pipeline: For defining the CI/CD workflow as code (Jenkinsfile).
  • SonarQube Scanner Plugin: Enables the withSonarQubeEnv block to trigger code quality checks.
  • Credentials Binding Plugin: Safely provides passwords/tokens (like JFrog credentials) via the withCredentials block.
  • Publish Over SSH: Necessary for the sshPublisher step to deploy artifacts to Tomcat servers.
  • Docker Pipeline Plugin: Allows Jenkins to build and push Docker images using the withDockerRegistry step.

5. Target Servers & Infrastructure Requirements

Server Role IP / URL Requirements & Specifications
Jenkins Server Any IP (Master Node) Requires Java, Maven, Docker, and Git installed on the underlying instance to execute pipeline steps.
SonarQube Server http://localhost:9000 (Default) Requires minimum 2GB RAM. Used for Static Application Security Testing (SAST) and code quality analysis.
JFrog Artifactory http://13.218.210.102:8081 Repository: libs-release-local. Used for storing .war artifacts safely. Requires proper port bindings and credentials.
Tomcat App Server 98.89.2.8 User: ubuntu. Target path: /opt/tomcat/webapps. Needs SSH key setup from Jenkins for deployment.
Docker Registry Docker Hub User: nimbuswiztech. Used to store the built container image (petclinic) for future deployments to Kubernetes or ECS.
