Docker Mastery Lab Guide

Your complete practical companion for containerization. Follow along with the live classroom demonstration, copy exact commands, track your milestones, and build your first custom production-ready Docker container.

Hands-On Lab Milestones Checklist

Check off each milestone as you execute the demonstration in your terminal:

Task 1: Verify Docker engine is running on your machine (docker version).
Task 2: Download the official Nginx Alpine image from Docker Hub (docker pull nginx:alpine).
Task 3: Start the Nginx container in background mode with port forwarding on 8080 (docker run -d --name my-nginx -p 8080:80 nginx:alpine).
Task 4: Open browser to http://localhost:8080 and verify "Welcome to nginx!" appears.
Task 5: Inspect live HTTP requests using log streaming (docker logs -f my-nginx).
Task 6: Open an interactive shell inside the running container (docker exec -it my-nginx sh).
Task 7: Test local hot-reloading using a Bind Mount (-v $(pwd)/html:/usr/share/nginx/html:ro).
Task 8: Write a Dockerfile and custom index.html file on host disk.
Task 9: Build your custom image using docker build -t devops-portal:v1 . and launch it on port 8082.
Task 10: Clean up stopped containers and understand container lifecycle (docker stop, docker rm).

Step-by-Step Demonstration Walkthrough

Figure 2: Virtual Machines vs. Docker Containers — OS-Level Virtualization sharing the Host Kernel

Figure 3: Docker Engine Architecture — CLI Client, REST Unix Socket, dockerd Daemon, containerd, runc, and Linux Kernel

Phase 1: Downloading the Nginx Base Image Lab Step 1

Run the following command in your terminal. Docker will query Docker Hub, download the read-only layer digests, and cache them locally:

terminal 
$ docker pull nginx:alpine
$ docker images
💡 Why Alpine? Alpine Linux is an ultra-minimal distribution designed for security and speed. The entire base image is only ~5 MB, making total download and container startup lightning-fast compared to standard Ubuntu or Debian images (~150 MB+).
Phase 2: Launching the Nginx Container & Port Mapping Lab Step 2

Now launch the container in the background with port forwarding:

terminal 
$ docker run -d --name my-nginx -p 8080:80 nginx:alpine
$ docker ps

Flag Breakdown:

  • -d: Detached mode. Container runs in the background.
  • --name my-nginx: Sets container name to my-nginx instead of a random string.
  • -p 8080:80: Maps Host Port 8080 to Container Port 80.

👉 Test: Visit http://localhost:8080 in your web browser. You should see Welcome to nginx!

Phase 3: Watching Real-Time Access Logs Lab Step 3

Streams standard output from the web server. Refresh your browser to see requests appear:

terminal 
# Stream logs live (press Ctrl + C to exit)
$ docker logs -f my-nginx
Phase 4: Entering the Container Filesystem (`docker exec`) Lab Step 4

Open an interactive shell session inside the container's isolated Linux environment:

terminal 
# Jump inside the container
$ docker exec -it my-nginx sh

# Look at the web root and active processes
/ # ls -la /usr/share/nginx/html
/ # ps aux
/ # exit
Phase 5: Local Hot-Reloading with Bind Mounts Lab Step 5

Link a folder from your laptop directly into the container's Nginx document root:

terminal 
# Create local folder & test page
$ mkdir -p ~/docker-demo/html
$ cd ~/docker-demo
$ echo "<h1 style='color:#06b6d4;'>⚡ Live Local Host Mount</h1>" > html/index.html

# Launch container with bind mount
$ docker run -d --name dev-nginx -p 8081:80 -v $(pwd)/html:/usr/share/nginx/html:ro nginx:alpine

# Open http://localhost:8081, edit html/index.html on your laptop, and refresh!
$ echo "<h1 style='color:#10b981;'>🎉 Updated without rebuilding!</h1>" > html/index.html
02

Building a Custom Production Image (`Dockerfile`)

Bind mounts are great for local hacking, but production deployments require an immutable image containing your actual code.

File 1: `index.html`

index.html 
<!DOCTYPE html>
<html>
<head>
  <title>DevOps Production App</title>
  <style>
    /* removed body styles for layout consistency */
    .badge {
      background: #06b6d4;
      color: #04252e;
      padding: 6px 16px;
      border-radius: 999px;
      font-weight: bold;
    }
  </style>
</head>
<body>
  <span class="badge">CONTAINER READY</span>
  <h1>Welcome to My Custom Docker Image</h1>
  <p>Built via Dockerfile and deployed in isolated container.</p>
</body>
</html>

File 2: `Dockerfile`

Dockerfile 
# 1. Base image
FROM nginx:alpine

# 2. Metadata
LABEL author="Student Engineer"

# 3. Copy application code into container
COPY index.html /usr/share/nginx/html/index.html

# 4. Expose documentation port
EXPOSE 80

# 5. Runtime command
CMD ["nginx", "-g", "daemon off;"]

Build and Run Your Image

terminal 
# 1. Build image with tag 'devops-portal:v1' (don't forget the trailing dot!)
$ docker build -t devops-portal:v1 .

# 2. Run your custom image on port 8082
$ docker run -d --name my-portal -p 8082:80 devops-portal:v1

# 3. Open browser: http://localhost:8082

04

Lab Troubleshooting Matrix

💥 Port Already In Use

bind: address already in use

Quick Fix: Map to an alternative port (e.g. -p 8085:80) or stop the process running on that port.

⚠️ Container Disappears Immediately

docker ps is empty; docker ps -a shows Exited (0).

Quick Fix: The container process completed. Ensure the service runs in foreground (e.g. daemon off;).

🔌 Cannot Connect to Docker Daemon

Cannot connect to the Docker daemon at unix:///var/run/docker.sock

Quick Fix: Start Docker Desktop or run sudo systemctl start docker.

Self-Assessment Quiz

1. Which command allows you to view both running and stopped containers?
A) docker status
B) docker ps -a
C) docker images -all
Correct! `docker ps -a` shows all containers, regardless of whether they are active, paused, or exited.
2. What does the `-p 3000:80` flag do when running a container?
A) It limits memory to 3000 MB and CPU to 80%.
B) It forwards traffic from host port 3000 to container port 80.
C) It starts 3000 replicas on port 80.
Correct! Syntax is `-p <host_port>:<container_port>`. Traffic to host:3000 goes to container:80.
3. What is the role of the trailing dot `.` in `docker build -t app:v1 .`?
A) It specifies the current directory as the build context for Docker to find files.
B) It tells Docker to run in root mode.
C) It suppresses warning logs.
Correct! The dot defines the build context directory uploaded to the Docker daemon.
